## Contracts and bounds

`demo.start({})` returns 256-bit random Alex/Sam capabilities and an expiry. Only SHA-256 hashes are persisted. `demo.board({token})` exposes only the capability's synthetic family; Sam has separate note/handled authority, while Alex can run/reset. Authors come from the verified capability, never the caller. The scheduled expiry flag invalidates existing subscriptions; mutations also enforce the exact 30-minute deadline. No private API accepts a demo capability.

`demo.runSample({token,sample})` accepts only `suspicious`, `legitimate`, `unverifiable`; stored fixed forwards enter `pipeline.verifyCase`. There is one stored case per sample; repeat returns that case. A failed workflow can restart on the same case only after it is terminal. Reset waits for terminal workflows, removes case/evidence/workflow records and preserves both participant capabilities. Reset is limited to once per minute and three times per session; total runs are limited to 12. Notes: 500 characters each, 20 per case, plus a session collaboration rate limit. Start is globally bounded to 30/hour with burst 10, at most 100 retained sessions; global runs have a 60/minute rate with burst 12. Expiry cleanup retries at most ten times for active jobs, retaining a bounded slot for operator recovery rather than deleting an active workflow.

Optional `families.demoSessionId` and `cases.demoSessionId/demoSample` isolate demo records. `cases.rawStorageId` becomes optional for fixed demo messages only; real inbound still requires it, and private extract/reply paths reject missing storage. All raw-storage consumers were traced. Shared `cases.boardCase(ctx,c)` preserves the original board projection; HAC-72 should add optional reminder projection there and exclude both demo markers from all notification scheduling/delivery.

The demo uses the existing deterministic extraction fallback and reviewed seed registry, with no OpenAI, Firecrawl or AgentMail requests. Shared `cases.beginReply` always leaves a demo draft unsent even with provider credentials; `cases.setReply` rejects sent-state recording for demos. Families have no memberships, registered routes or recipient addresses. The UI labels this preview behavior and distinguishes published-detail matches from sender authentication.
